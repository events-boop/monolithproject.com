## Subscription setup and limitations

Server-only configuration: `SUNSETS_SIGNUP_PROVIDER=flodesk`, `SUNSETS_FLODESK_API_KEY`, `SUNSETS_FLODESK_EVENT_SEGMENT`, `SUNSETS_FLODESK_RADIO_SEGMENT`. The segments must differ. These are isolated from the existing site-wide lead provider; no existing email automation was changed. See [Flodesk API documentation](https://developers.flodesk.com/) for API key authentication, subscriber upsert and double opt-in.

`GET /api/sunsets/subscriptions` currently returns both audiences unavailable. Forms are visibly disabled, not disguised mailto subscriptions. `POST` fails with 503 when unconfigured, never a false success. Provider upsert avoids duplicate people, while selected segment membership distinguishes the lists. Previously unsubscribed/suppressed addresses are not presented as successful subscriptions. **Real provider delivery and inbox confirmation have not been tested.** Mock tests do not establish delivery.
